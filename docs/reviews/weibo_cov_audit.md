## 事先固定的研究范围

采用 2020-09-01 至 2020-11-30 共 91 天连续月表，兼顾连续观察时间和下载体量。为适配现有后续分析的内存开销，在看到结果前固定按帖 ID 选取约 1/32。对去除首尾空白的 `_id` 按 UTF-8 求 SHA-256，前八字节按无符号大端整数取模 32，保留余数 0。相同 ID 的重复记录使用相同选择。配置见 [weibo_subset.json](../../configs/weibo_subset.json)。剩余天数和测试正例是否足够由 Chang 在覆盖审计后判定。缩小后的样本会减少稀有话题、根帖匹配和热点候选，分母均须注明。

## 审计口径

- 文件按年月顺序、记录按源文件顺序读取，支持 UTF-8 BOM、CSV 引号、逗号和多行正文。先对照团队已记录的网盘目录字节数，再计算原始文件 SHA-256。作者未在该清单发布校验摘要，因此这里的哈希用于标识实际接收版本和核对传输。
- 日期使用北京时间，拒收格式错误或带时区偏移的日期。基于 `created_at` 的日期选择，保留原始非空正文和字符串 ID。字段数错误单列计数；解码、CSV 语法或表头异常会终止导入。
- 行数对账：原始记录 = 列宽异常 + 时间无效 + 窗口外 + 帖 ID 缺失 + 未命中哈希桶 + 选中。选中 = 必需字段无效 + 去重前有效。去重前有效 = 重复 + 最终留存。跨月全局按 `mid` 保留第一条有效记录，按时间和 ID 固定输出顺序。
- 每个源文件记录字段缺失、可解析日期覆盖、日期与文件月份不符的行数。规范表记录逐日有效帖数，覆盖日历包括零帖日。检查零帖日时，先区分原始月表缺口和抽样后零帖。互动数中的零原样保留；缺失或不合法的非负整数置空，并生成各字段缺失标记，异常值另计。互动数对应采集快照，历史预测须证明当时可见。
- 根帖非空率 = 有根帖引用的留存帖数 / 全部留存帖数。端点匹配率 = 引用能在子集 `mid` 找到的留存帖数 / 有根帖引用的留存帖数；同时报告自引用数及剔除自引用后的匹配率。分母为零记为 `null`。匹配不足可能来自采集边界、筛选和抽样；此字段仅支持对可观察根帖引用的描述。
- 审计 JSON 含每个源文件字节数/哈希、所有行数、有效用户数、覆盖、互动缺失和关系指标。来源清单及规范表由程序在本地发布，只有聚合审计可进 Git。输出签发前检查同名旧版本；不同版本需要单独保全和复核。
